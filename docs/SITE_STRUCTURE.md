# Site Structure

This site is now organized as an Astro academic site. The active code lives in these places:

```text
src/
  components/          Reusable Astro components
  content/             Markdown content collections
    blog/              Blog posts
    photography/       Photography series
    publications/      Publication records, figures, BibTeX files
  layouts/             Shared page layout
  lib/                 Shared data and helpers
  pages/               Routes and page templates
public/
  css/site.css         Main stylesheet
  js/site.js           Interactions, menu, lightbox, local photo likes/comments
  publications/        Generated mirror of publication figures and BibTeX files
  uploads/             CV, avatar, photography assets, publication assets
scripts/               Scholar maintenance scripts
docs/                  Maintenance notes
```

Generated or local-only folders should stay out of git:

```text
dist/                  Build output
.astro/                Astro cache and generated types
node_modules/          Installed npm packages
```

Legacy Hugo/Jekyll files were removed from the working tree. The active site is the Astro tree above.

## Update The Homepage

Edit:

```text
src/pages/index.astro
```

This controls the landing page layout, intro copy, homepage news preview, research preview, publication preview, and photography preview.

## Update Profile Text And Links

Edit:

```text
src/pages/index.astro
```

Look for the intro section near the top of the file. That is where the biography, supervisor links, GitHub, Google Scholar, LinkedIn, CV, and email links live.

## Update The Profile Photo

Replace:

```text
public/uploads/avatar.jpg
```

Keep the same filename if you do not want to edit code. Use a portrait-oriented image for best results.

## Update News

Edit:

```text
src/lib/news.ts
```

The homepage shows the first few items automatically. The full archive is:

```text
src/pages/news.astro
```

## Update Research Directions

Edit:

```text
src/lib/research.ts
```

Each research direction defines its title, summary, image, long description, and related publication slugs. The list page is:

```text
src/pages/research.astro
```

The individual research pages are generated by:

```text
src/pages/research/[slug].astro
```

## Update Publications

Each publication has its own folder:

```text
src/content/publications/<publication-slug>/index.md
```

Optional assets live in the same folder:

```text
featured.png
featured.jpg
cite.bib
```

Common fields to edit in `index.md`:

```yaml
title:
date:
authors:
venue:
status:
abstract:
pdf:
project:
doi:
tags:
```

The publication list and homepage cards use these Markdown files automatically.
`npm run build` mirrors publication images and BibTeX files into `public/publications/` before Astro builds, so pages can serve them as static files.

To use the first/main figure from a paper PDF, run:

```bash
npm run extract:figures -- --overwrite
npm run build
```

The extractor looks for PDF links in `cite.bib` or arXiv/OpenReview links, extracts embedded images from the first few PDF pages, and writes the first substantial embedded image as `featured.png`. It deliberately does not use a full-page screenshot fallback. Automatic extraction is best-effort: for papers with vector-only figures, publisher paywalls, or no PDF link, replace `featured.png` manually with the first figure you want.

To refresh publication data from Google Scholar:

```bash
npm run sync:scholar
```

Google Scholar may block automated requests. If that happens, edit the publication Markdown files manually or rerun the sync later.

## Update Photography

The photography page cover is controlled here:

```text
src/content/photography/page.md
```

Edit these frontmatter fields:

```yaml
cover: "/uploads/photography/iclr-rio-2026/IMG_6409.JPG"
cover_alt: "Christ the Redeemer in Rio de Janeiro"
cover_label: "Rio de Janeiro, Brazil"
cover_title: "ICLR Rio 2026"
cover_href: "/photography/iclr-rio-2026/"
```

Each photography series has its own folder:

```text
src/content/photography/<series-slug>/index.md
```

Put photo files in:

```text
public/uploads/photography/<series-slug>/
```

Then reference them in the Markdown frontmatter:

```yaml
order: 1
cover: "/uploads/photography/<series-slug>/cover.jpg"
gallery:
  - src: "/uploads/photography/<series-slug>/01.jpg"
    alt: "Short description"
  - src: "/uploads/photography/<series-slug>/02.jpg"
    alt: "Short description"
```

The first gallery image becomes the hero image on the series page. The cover image becomes the atmosphere/background image.

The album order on the photography page is controlled by `order` first. Smaller numbers appear earlier. If `order` is missing, albums fall back to newest `date` first.

Photography pages are static. Shared likes or comments would require adding a backend service.

## Update Global Layout, Menu, And Theme

Edit:

```text

public/css/site.css
public/js/site.js
```

`BaseLayout.astro` controls the shared header, menu, opening animation, footer, and CSS/JS asset version strings.
